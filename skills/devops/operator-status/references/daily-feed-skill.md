# Daily Feed Dashboard

Cooper's personal command-center dashboard. Combines blocked kanban items (with recommended unblock actions), task status overview, and daily cron digests in one dark-mode page.

## Architecture

- **Project:** `~/feed/` — Vite + React + TypeScript + Tailwind + shadcn/ui
- **Block:** @shadcnblocks `dashboard9` (Overview Dashboard with sidebar, stat cards, charts, table, progress list)
- **Server:** launchd `ai.cooper.feed-server` serving `~/feed/dist/` on port 8654
- **Data sources:**
  - `email-triage` kanban board (blocked tasks with comments, summaries)
  - Cron job outputs (`~/.hermes/cron/output/<job_id>/`)
  - Recommendations (`~/.hermes/feed/recommendations.json`)
- **Build:** `python3 ~/.hermes/scripts/build-feed.py` → generates `src/feed-data.json` → runs `bun run build`
- **Cron:** Daily Feed Builder (job_id: `9acdbe616b8f`) at 9:30am PT
- **Feed Signal Collector** (job_id: `8f134b8a1a93`) at 7am PT — collects X posts + HN stories
- **Updated crons** to write JSON: Daily Comms Triage (`969ec44641bf`), Daily Todo Scan (`8176f001451b`)

## Cron JSON Schema

Crons write structured JSON to `~/.hermes/feed/cron-json/<name>.json`. See `references/cron-json-schema.md`.
The build script reads all `*.json` files from that directory and includes them as `cron_json` in the feed data.
The dashboard renders items from cron JSON as cards in sections: Recent Messages, X Posts, HN Stories, and per-cron sections.

## Recommendation Format

Each blocked task gets a recommendation in `recommendations.json`:

```json
{
  "t_XXXXX": {
    "why_blocked": "short reason",
    "category": "secret|decision|draft|confirmation",
    "actions": [
      {
        "kind": "copy",
        "label": "Copy prompt to...",
        "prompt": "ready-to-paste Hermes prompt",
        "recommended": true
      },
      {
        "kind": "secret",
        "label": "Copy prompt with secret",
        "placeholder": "where to find the secret",
        "prompt_template": "prompt with {{SECRET}} placeholder"
      },
      {
        "kind": "choice",
        "label": "Choose:",
        "options": [
          {"label": "Option A", "recommended": true, "prompt": "..."},
          {"label": "Option B", "recommended": false, "prompt": "..."}
        ]
      }
    ]
  }
}
```

## Manual Rebuild

```bash

```

```bash

cd ~/feed && bun run build
```

## Server Management

```bash
# Status
launchctl list | grep feed-server
curl -s -o /dev/null -w "%{http_code}" http://localhost:8654/

# Restart
launchctl unload ~/Library/LaunchAgents/ai.cooper.feed-server.plist

# View logs
tail -20 ~/.hermes/logs/feed-server.log
```

## Updating the Dashboard Layout

The main component is at `~/feed/src/components/dashboard9.tsx`. It uses installed shadcn UI primitives (sidebar, card, table, badge, button, chart, collapsible, scroll-area). To add new sections or modify the layout, edit this file and rebuild.

## Pitfalls

- **file:// protocol**: ES modules don't load via `file://` — must use the HTTP server on port 8654
- **Dark mode**: The `class="dark"` is set on `<html>` in `~/feed/index.html`. All CSS variables are dark-themed in `src/index.css`.
- **Data freshness**: The feed only updates when `build-feed.py` runs (cron at 9:30am or manual). The page auto-refreshes every 10 min via meta refresh.
- **Recommendations**: Must be regenerated by the Daily Feed Builder cron — they're LLM-generated based on task summaries and comments.
- **Cron jobs.json field name**: The raw file at `~/.hermes/cron/jobs.json` uses the `id` field for job identifiers (NOT `job_id`). The `cronjob` tool's `list` action returns `job_id` in its API response, but `load_cron_meta()` in `build-feed.py` must read `j['id']` from the raw file. This mismatch caused cron digest names to show as "MISSING" until fixed.
- **shadcnblocks without MCP**: If `hermes mcp list` returns no MCP servers, you can still access the @shadcnblocks registry directly via curl. See `references/shadcnblocks-api.md`.
- **Auxiliary vision config**: Setting `auxiliary.vision.provider` and `auxiliary.vision.model` alone is NOT enough — you must also set `auxiliary.vision.base_url` (e.g., `https://openrouter.ai/api/v1`) and `auxiliary.vision.api_key` explicitly. Without these, vision falls back to the main model's LiteLLM proxy and fails on non-multimodal models.

## User Preferences (Cooper)

- **Dark mode only** — the feed should always be in dark mode
- **Choose templates before building** — when selecting shadcnblocks, present 3-4 options via `clarify` tool before installing. Cooper wants to see descriptions and pick, not have the agent decide silently.
- **Clickable elements** — all cards (X posts, HN stories, messages) should be clickable links that open in new tabs. Sidebar items should scroll to their sections.
- **Not just todos** — the feed should surface a broad digest: blocked kanban items, recent messages (email/Slack/iMessage), interesting X posts, HN stories, and cron digests — not just a todo list.

## Interactive Features

The dashboard supports:
- **Sidebar navigation** — clicking sidebar items smooth-scrolls to sections via `scrollIntoView`. Section IDs are set on wrapper divs (`section-overview`, `section-blocked`, `section-messages`, `section-xposts`, `section-hn`, `section-ready`, `section-digests`).
- **Clickable cards** — `FeedItemCard` wraps the entire card in an `<a>` tag when `item.link` is present, opening in a new tab.
- **Copy-to-clipboard** — action buttons (copy/secret/choice) copy Hermes-ready prompts to clipboard with a toast notification.
- **Collapsible sections** — blocked task comments and cron digest outputs use `Collapsible` for expand/collapse.
